# crucibleinnovation.com

Marketing site for Crucible (studio, `/`) and Crucible Sites (websites for local businesses, `/sites`, the page the business-card QR opens). Owner: Jacob Schopp. Read `README.md` for setup, deploy and the launch TODO list.

## Stack and commands
- Next.js 15 App Router, **static export** (`output: 'export'` → `out/`), TypeScript, Tailwind CSS v4. No server: no API routes, no `next/headers`, no runtime redirects, no image optimizer.
- `npm run dev` · `npm run build` · `npm run typecheck` · `npm test` (Playwright smoke tests against `out/`, so build first; locally set `PLAYWRIGHT_BROWSERS_PATH` if browsers live elsewhere).
- Deploy: push to `main` → `.github/workflows/deploy.yml` builds and publishes to GitHub Pages (custom domain via `CNAME`). PRs run `.github/workflows/ci.yml` (typecheck, build, Playwright, Lighthouse CI with `lighthouserc.json`).
- Repo variables (optional): `UMAMI_WEBSITE_ID` (analytics), `FORMSPREE_ID` (in-page form posting; without it the form composes an email via mail app/Gmail/Outlook).

## Where things live
- Copy and content: `data/*.ts` (`site.ts` founder/email/Formspree, `ventures.ts`, `work.ts`, `pricing.ts`, `faq.ts`). Prefer editing data over components.
- Pages: `app/page.tsx`, `app/sites/page.tsx`, `app/not-found.tsx`, `app/ventures/[slug]` (generated for live ventures without `href`).
- Brand: tokens and all effect CSS in `app/globals.css`; `components/SplitRing.tsx` (geometry in `lib/splitRing.ts`, shared with favicon), `components/Wordmark.tsx` (dotless ı + Ember dot).
- Motion: no animation library. Reveals = `[data-reveal]` / `[data-words]` / `[data-cast]` + one IntersectionObserver (`components/InView.tsx`) + CSS. Scroll-linked effects use `lib/scroll.ts` (`data-scroll="view|enter|pin|reveal|read"` → CSS `var(--p)`, or `trackScroll()`); progress eases toward the scroll position with a capped speed. Pinned scenes are `Ignition` (home opening, see 3D below), `BuildStage` (/sites opening, with the live concept sites in `LiveSite`) and `Thesis`. "Casting" (something poured in behind an Ember front) uses the shared `.cast-*` classes.
- The liquid (`lib/liquid/`, mounted by `components/Liquid.tsx`): the whole site is a dark liquid. It is an analytic wave field shared by the CPU `sample(x, docY)` -> `{h, gx, gy}` and the shader (`field.ts`, `shader.ts`; no GPU sim, no readback): a ring buffer of wave sources in page CSS px plus an always-on idle swell. Sources come from pointer move/drag, click/tap, scroll (a resting cursor emits along its page-space path) and floaters. `loop.ts` (`onFrame`) is the one rAF loop for the field, floaters and 3D scenes; it idles in hidden tabs. `render.ts`/`liquidWorker.ts` render it in a Web Worker on an OffscreenCanvas (main thread if unsupported); `engine.ts` holds adaptive quality (render scale, fps, source count step down and back up) and detects software GL (SwiftShader/llvmpipe: CI, PageSpeed), which starts at the lowest step and never gives up. `?liquid=full` pins the top step (use for screenshots). Layering: one fixed, pointer-events:none canvas at `z-index:-1` paints the dark itself, so every section background is transparent and content (text, images, 3D canvases) paints above it. Section effect canvases (Thesis flames, footer furnace) are transparent where there is no heat.
- Floating (`lib/liquid/float.ts`: `startFloat`, `buoy()`): elements ride the waves through CSS `translate`/`rotate` (so they compose with `transform` reveals; layout never changes). `data-float="strong|heading|block|text|none"`: headings (h1/h2/`.h-display`/`.h-section`) and text (p/li/a/button in `main`) are automatic, `block` is explicit (portraits), `strong` is for 3D objects (they float inside their scene via `sample()`/`buoy()`). Excluded always: nav, header, the /sites form (and ancestors holding a form), dialogs, fixed and inline elements. Off under reduced motion.
- 3D (`lib/gl3d/`, tiny WebGL2, no three.js): `core.ts` (`createStage`), `geometry.ts` (bevelled extrusions from `lib/splitRing.ts`: `logoPieces()`, moulds), `materials.ts` (procedural 'cast' | 'core' | 'hot' | 'sand'; no Blender, no assets), `ingots.ts`/`ingotPose.ts`, `logoScene.ts` + `pour.ts`/`pourGeo.ts` (the home logo: a crucible pours white-hot metal into a sand mould that cools to bone, then the ring floats and drives the Ignition story), `ingotScene.ts` (venture ingots, freestanding on the liquid). `Ignition` and `IngotScene` (`components/`) mount them in their own in-flow canvases: loaded after load + idle, created near the viewport and released when far; the 3D logo (target state) runs in a Web Worker, software GL starts at the lowest quality step, and the headline is visible from first paint. Static version (reduced motion, no JS, no WebGL): the SVG logo and transparent ingot stills in `public/film/ingots`, captured from our own renderer by `scripts/ingot-stills.mjs`; `scripts/venture-og.mjs` builds the venture share images (`public/og`) from them. Story and mould squares are upright everywhere.
- Section effects: `Thesis` heats 293 K to 1811 K as you scroll, with flames from `lib/gl/molten.ts` (transparent where cold; reach and speed follow the heat). The footer is dark with a furnace under the wordmark (`components/Furnace.tsx`, `FurnaceGL.tsx`, `lib/gl/furnaceGL.ts`: its own copy of the shader, so Thesis edits can't break it; loops run only while on screen via `[data-heat]`/`data-live` in `InView`). `BuildStage` sparks: `lib/gl/sparks.ts`.
- Tiers: `lib/tier.ts`. Every visit gets rich (the liquid, `lib/gl3d/*` and `lib/gl/*`, loaded after load + idle): Jacob's call, there is no low-bandwidth version. Light (CSS/SVG, stills) is only for reduced motion, no JS, and a scene that can't start (no WebGL). `?tier=rich|light` forces one. Every rich effect still needs that light version, and must lower its own quality on slow frames rather than stall or give up. Headline and nav must not wait on WebGL. Brand sayings are placed individually where they fit. The co-founders' own accounts (one chapter each on the home page, Jacob first) live in `data/story.ts`, the team in `data/team.ts`: ASCII portraits (`public/team/<name>.webp`, dark ink on transparent) recoloured to bone for the black by `scripts/bone-portraits.py` into `public/team/*-bone.webp`; never commit real photos. Software GL (no GPU) must stay cheap: the liquid is in a Worker, 3D starts low.
- Images: showcase screenshots are rendered from `showcase-src/*.html` by `showcase-src/render.mjs`, which also writes the `-640`/`-960` variants that `lib/imageLoader.ts` serves. New images outside `/showcase/` are served as-is.
- Print: `brand/business-card.html` → `node brand/render-card.mjs` → `brand/business-card.pdf`.

## Rules (from the PRD)
- Never write "LLC", "incorporated", a street address, or any payment details (Venmo etc.). Payment copy: "No payment until you've approved the design."
- No fabricated testimonials, client logos, reviews or stats. Showcase items stay labeled `Concept` until they are real clients.
- Colour means temperature. Ember (`--ember`) is the only accent and means hot (active, interactive, live): about 3 Ember elements per screen at most. `--ember-hot` only inside hot metal. Cooled surfaces flip to bone (`--cool`, `--ink`, `--ink-dim`, `--ember-deep` for Ember text on bone).
- Placeholders are marked `// TODO(jakob)`.
- Quality bar: Lighthouse mobile ≥ 95 on all four categories, `/sites` first-load JS well under 200 KB gzipped, no horizontal scroll at 360px, AA contrast, visible Ember focus rings.
- No gradient text and no second display face: hierarchy comes from Archivo's size, weight and width (`.wide`, `.h-display`, `.h-section`). The one exception is "alloyed" in the home opening, which is cast white-hot and cools (`.ig-cool`).
- Design rules live in `.claude/skills/unslop/SKILL.md`; `npm run unslop` checks what a machine can (headings without periods, no Instrument Serif or mono outside data, no wide-tracked caps, no decorative numbering, no dead zones on the home page).
