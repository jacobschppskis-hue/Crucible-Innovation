# crucibleinnovation.com

Marketing site for Crucible (studio, `/`) and Crucible Sites (websites for local businesses, `/sites`, the page the business-card QR opens). Owner: Jacob Schopp. Read `README.md` for setup, deploy and the launch TODO list.

## Stack and commands
- Next.js 15 App Router, **static export** (`output: 'export'` → `out/`), TypeScript, Tailwind CSS v4. No server: no API routes, no `next/headers`, no runtime redirects, no image optimizer.
- `npm run dev` · `npm run build` · `npm run typecheck` · `npm test` (Playwright smoke tests against `out/`, so build first; locally set `PLAYWRIGHT_BROWSERS_PATH` if browsers live elsewhere, or `PW_CHROMIUM_PATH` to a Chromium binary).
- Deploy: push to `main` → `.github/workflows/deploy.yml` builds and publishes to GitHub Pages (custom domain via `CNAME`). PRs run `.github/workflows/ci.yml` (typecheck, build, Playwright, Lighthouse CI with `lighthouserc.json`).
- Repo variables (optional): `UMAMI_WEBSITE_ID` (analytics), `FORMSPREE_ID` (in-page form posting; without it the form composes an email via mail app/Gmail/Outlook).

## Where things live
- Copy and content: `data/*.ts` (`site.ts` founder/email/Formspree, `ventures.ts`, `work.ts`, `pricing.ts`, `faq.ts`). Prefer editing data over components.
- Pages: `app/page.tsx`, `app/sites/page.tsx`, `app/work/page.tsx`, `app/ventures/page.tsx`, `app/not-found.tsx`, `app/ventures/[slug]` (generated for every venture without `href`: live ones, and teasers for those still forging).
- Brand: tokens and all effect CSS in `app/globals.css`; `components/SplitRing.tsx` draws the mark, the lattice ring (geometry in `lib/splitRing.ts`: `RING` rings r 27/15 on one 3-unit lattice, `cells()` = 20 upright cells (every other cell of `raster(R)`), the first cell at each arc end welded to it (`arcOutline(r)`), no free cell overlapping an arc; `tests/mark.spec.ts` enforces it). The same mark everywhere: the static copies (favicon, apple icon, inline marks in `brand/*.html`) come from `node --experimental-strip-types scripts/mark-assets.mjs`, then `node brand/render-og.mjs` and `node brand/render-card.mjs`. `components/Wordmark.tsx` (dotless ı + Ember dot). Fonts: Archivo is self-hosted as one variable file (`app/fonts/`, wght 400-800, wdth 100-125, Latin subset; recipe in `README.md`); the concept sites' Instrument Serif loads after load + idle via `html[data-fonts]` (`releaseConceptFonts` in `lib/tier.ts`) with a metric-matched fallback until then. Component CSS is imported by the component/page that uses it, not the layout (only globals and `Sites.css` are global).
- Motion: no animation library. Reveals = `[data-reveal]` / `[data-words]` / `[data-cast]` + one IntersectionObserver (`components/InView.tsx`: it hides (`data-arm`) only what it measured below the viewport and shows anything in view or above at once; arming itself hides instantly and, after jumps/restores, the entrance is skipped too (`data-snap`), so nothing on screen ever fades out; a sweep on scroll/scrollend/resize catches anything in view or passed, so fast jumps never leave content hidden) + CSS. `content-visibility` estimates (`cv-auto`, `--h-sm`/`--h-lg`) are measured content-box heights (padding excluded; 390 / 1440 wide), and InView renders each deferred section once after load so real sizes are remembered. Scroll-linked effects use `lib/scroll.ts` (`data-scroll="view|enter|pin|reveal|read"` → CSS `var(--p)`, or `trackScroll()`); progress follows the scroll position as an exact critically damped spring per element (time constant 0.035 s, `view` 0.03, growing to 0.075 s for gaps ≥ 0.3; velocity carried over, never past the target), with no speed cap and no deadline or landing snap (one snapped every ~0.7 s of a steady scroll: never add a "land at once" rule back; a scene that needs a gentler curve eases its own value), yet any jump lands within ~0.57 s (`<html data-scroll-settled>` when every tracked progress is at target). Pinned scenes are `Ignition` (home opening, see 3D below), `BuildStage` (/sites opening, with the live concept sites in `LiveSite`) and `Thesis`; `data-scroll="pin"` also drives `Process`, the `Ventures` track and the /work `Stack`s. "Casting" (something poured in behind an Ember front) uses the shared `.cast-*` classes.
- The liquid (`lib/liquid/`, mounted by `components/Liquid.tsx`): the whole site is a dark liquid. The surface is a damped wave-equation grid on the main thread (`sim.ts`: 8 px cells (7 on phones), 120 Hz substeps, `SIM.damp` 1.2/s, anchored to the page, sponge edges, no cost while quiet; two bands summed into the displayed heights: the main one (`SIM`, 420 px/s) for cursor, taps, fingers and floaters, and `FINE` (170 px/s, damp 4/s, `Stamp.b` 1) for the scroll wake only, each stepped only inside a box that grows faster than its waves) plus an analytic idle swell (`swell.ts`: `swellAt` on the CPU, `swellGLSL` in shaders, the same sum). `input.ts` makes the waves: a moving pointer is ONE coherent vibrating source on the clock's own phase (`sing`: `TUNE.osc` 8.5 Hz, stamped at every substep along its path, strength eased from its speed; no mean, so no trough) that hands over to drops along the path above Mach 1.6-3 (page-space speed / `SIM.speed`: one every `TUNE.dgap` 10 px, strength per px of path, so a fast drag or flick leaves a V of ridges with glints); never per-drop phases at moderate speed (they cancel at the pointer), a tap is one bigger drop, finger drags make a wake, scrolling past a resting cursor or finger leaves passage-locked drops in the `FINE` band (a narrow V behind the pointer that fades fast; in the main band a sub-Mach-1 source can only make rings that enclose the pointer, a "sonar tunnel"), floaters shed small drops (`addSource(..., {kind: 'float'})` in `field.ts`). `shader.ts` shades it, never outlines it: a dark sky reflection, a warm Blinn-Phong key that is a horizontal strip of light, not a round lamp (`LOOK.coreX`), with crisp Ember glints on interaction waves only that fade in with curvature (`LOOK.crisp`: streaks along crests, no puddles; the swell moves only a faint sheen), no wave ever shades darker than the swell's own sheen (`LOOK.dip`; `LOOK.shade` 0.15 only for faces tilted away from the key), a faint caustic, the key capped behind text and portraits (`LOOK.textCap` 0.17: bone-dim body text stays AA at a glint's centre; the text mask from `float.ts`); no contour lines. `render.ts` posts each frame's heights to `liquidWorker.ts` (OffscreenCanvas); where the worker can't get WebGL2 (Playwright WebKit, older Safari) the same `engine.ts` draws on the main thread. `engine.ts` holds the quality steps (render scale, fps cap) and detects software GL (SwiftShader/llvmpipe: CI, PageSpeed), which starts low and never gives up; `?liquid=full` pins the top step (screenshots). It starts at the visitor's first scroll, pointer move or key (`firstUse()` in `lib/tier.ts`) or 2.5 s after load + idle, the floating on the next idle period after it. Layering: one fixed, pointer-events:none canvas (`canvas.liquid`) at `z-index:-1` paints the dark itself, so every section background is transparent and content (text, images, 3D canvases) paints above it. Section effect canvases (Thesis flames, footer furnace) are transparent where there is no heat. The nav is opaque `--ground` with no `backdrop-filter`: through any translucency the bright 3D under it (Sites bar, logo) showed as a grey box, and a blur over the liquid re-blurs every frame; never make it translucent. Selection: `::selection` is `--ember-tint` (the text keeps its colour); canvases, images, SVG and video are never selectable or draggable (base CSS, plus `draggable={false}` on decorative imgs for Firefox); the home opening `.ig` selects nothing but its paragraph; a mouse drag that starts on the liquid itself (no words under it) selects nothing (`keepDragsForWaves` in `Liquid.tsx`, a `selectstart` guard; keyboard, shift-click, touch and drags from text untouched), since dragging is how visitors make waves. A canvas React renders is never swapped out of the DOM (a worker-to-main fallback puts its fresh canvas next to React's spent one): a swapped node breaks every later client-side navigation (WebKit).
- One clock: `loop.ts` `onFrame(cb, {early})` is the only rAF and the only animation time (it idles in hidden tabs): early callbacks (layout reads) run first, then the liquid (input, grid step), then floaters and scenes. Workers keep no clock: they draw exactly the `t` the main frame posts and ack it (one tick in flight, the newest waits; the ingot worker acks only after a GPU fence on that frame (`afterGPU` in `ingotRunner.ts`), so a slow GPU paces the ticks instead of queueing frames); every renderer registers with `renderer(name, path)` and reports `done(t)`, paused while off screen. Test hooks: `window.__clock` (`pause`, `step(ms)`, `resume`, `settle(t)`, `renderers`, `now`; nothing adapts quality while `clockHeld()`), `window.__liquid` (`stats`, `sources`, `sample`, `grid`, `near`), `window.__float.list()`, `window.__logo` (per-piece logo poses); the liquid canvas carries `data-on`, `data-t` (time of the last drawn frame), `data-live` (input events that made waves in the last 3 s), `data-q`, `data-path` (worker | main).
- Floating (`lib/liquid/float.ts`: `startFloat`, `LEVELS`): each floater feels the surface under its whole box (`footprint()` in `field.ts`: mean height, best-plane tilt, mean slope) through second-order springs (no dead band, no hard clamps, a soft tanh limit only on large waves), written as CSS `translate`/`rotate` (so it composes with `transform` reveals; layout never changes). Text, headings and blocks get `data-fl` and ride grid + swell (never quite still); links and buttons get `data-fl-c` and ride interaction waves only, then rest exactly, so clicks land. `data-float="strong|heading|block|text|none"`: headings (h1/h2/`.h-display`/`.h-section`) and text (p/li/a/button in `main`) are automatic, `block` is explicit (portraits), `strong` is for 3D objects. One writer per element: the magnetic lean (`lib/liquid/lean.ts`, targets from `components/Magnetic.tsx`: primary buttons and `[data-pull]`) is added in `float.ts`; no CSS translate or transition on `.btn` or `[data-pull]`. 3D floats on the same surface: `samplePx`/`sampleGrid`/`footprint`/`heightPatch` (main thread), `patch.ts` (`samplePatch`/`footprintPatch`, DOM-free, for workers), `buoy3()` in `buoy.ts` (springs, `STRONG` limits). A 3D object sheds a ripple only when interaction waves rock it (never on a timer, never from the swell). Both 3D scenes compute their poses on the main thread every clock tick and post them with it; the renderer (worker or main) applies exactly those. The ingots: `samplePx` + `buoy3`. The logo (`logoScene.ts`): every piece on its own, the story's offsets plus `buoy3` on the surface under it (a cell or the core: five points across it, an arc: nine along it; the swell at a quarter of its height so the lattice stays readable at rest); the cursor pushes them through the same springs (its waves' energy pushes them away and tips them, the pointer is a soft hill that flattens once it rests; no clamp). There is no second wave model (`field.ts` has no `sample()`/`hooks`). Excluded always: nav, header, forms (and ancestors holding one), dialogs, fixed, inline and `display: contents` elements; nothing moves while a form field has focus. Off under reduced motion.
- 3D (`lib/gl3d/`, tiny WebGL2, no three.js): `core.ts` (`createStage`; `fixed: true` renders into an offscreen (MSAA) target scaled by quality and blits it to a fixed-size canvas, so a quality step never resizes the canvas: WebKit blanks a resized canvas for 1-3 frames), `geometry.ts` (bevelled extrusions from `lib/splitRing.ts`: `logoPieces()` = 2 arcs with their welded cells, 16 free cells, the core; `goldBar()`/`BAR`), `materials.ts` (procedural 'cast' | 'core' | 'hot' | 'ingot' | 'bar'; no Blender, no assets), `adapt.ts` (quality steps) + `watchdog.ts` (shared long-task watchdog). The home logo: `logoScene.ts` (main side) + `sceneWorker.ts` + DOM-free `logoRunner.ts`, pour in `pour.ts`/`pourGeo.ts`. There is no mould: a hairline ghost drawing of the mark (`.ig-ghost`, SVG in `Ignition.tsx` from `outlinePath(inset)`, each outline just inside its piece so the opaque metal hides it as it fills; scrubbed from the one clock: `Ignition.tsx` writes `--pt` on it from the pour's first frame, fade 2.7-3.05 s, gone before the metal sets) scans in, a crucible tips a thin white-hot stream into the core, trickles run down the arcs, the metal rises through the pieces' own shapes and cools to bone (the core stays orange), the ghost fades and the ring is released onto the liquid and drives the Ignition story; nothing breaks away. `.ig[data-pouring]` is set with `html[data-go]` when the pour starts, `section.ig[data-settled]` when it ends; the pour runs on the one clock from its first drawn frame; `?pourdebug` scrubs it from `window.__pourT` (the ghost/headline CSS from `--pt`). The ingots: one cast bar per venture (`ingots.ts`, `goldBar()`, no casing), the stamp cut into the top face as a relief map: Crucible Sites is cast bone metal ('bar': mirrors a night foundry, so a warm line runs along each fillet and a softbox slides over the top as it rocks; sand grain that fades by pixel footprint into roughness, round pits, the stamp cut darker; no Ember fill on bone, it turns the walls peach-pink) with the lattice ring and its name; bars still forging glow all over ('ingot': blackbody ramp, a drifting dark crust with glowing cracks) and carry their name alone (`// TODO(jakob)`: their own marks). Pose (`ingotPose.ts`): lying on the liquid, whose frame is tilted 35° toward the viewer (`TILT`), at a 3/4 yaw that turns about its normal as it passes (`YAW`); it floats on a five-point footprint (`createBarFloat`: `samplePx` -> `buoy3`) computed on the main thread (`ingotScene.ts`, one clock `renderer` per bar) and posted with the tick; `ingotWorker.ts` + DOM-free `ingotRunner.ts` (one worker per ingot canvas, the relief map drawn there with the site's Archivo via `FontFace`; the main-thread runner loads only if OffscreenCanvas WebGL2 is missing) draw exactly that `t` and ack `drawn` after its GPU fence; quality steps are monotone with at most one retry per level. The ingot canvas and still overhang the 8:5 host box by 14% above and below (5:4). `Ignition` and `IngotScene` (`components/`) mount them in their own in-flow canvases: loaded after load + idle, created near the viewport and released when far (a canvas given to a worker is spent: `IngotScene` re-keys it after each release); the headline is visible from first paint. Static version (reduced motion, no JS, no WebGL): the SVG logo and transparent ingot stills (`public/film/ingots/<slug>-{600,1200,2400}.webp`, the resting pose `REST`), captured from our own renderer by `scripts/ingot-stills.mjs`; `scripts/venture-og.mjs` builds the venture share images (`public/og`) from them. The mark's cells are upright everywhere (scattered ones tilt about 11° at most). Software GL drops MSAA and the bump taps and starts at the lowest step; `fidelity: true` (under `?liquid=full` and for the stills) keeps full quality.
- Section effects: `Thesis` heats 293 K to 1811 K as you scroll, with flames from `lib/gl/molten.ts` (a canvas over the bottom 30% of the scene only (`FLAME_SPAN`, `.thesis-gl`) at full device resolution (steps 1/0.75/0.5; software GL starts at 0.5, `?liquid=full` keeps 1): a streak-line fire: the age of the gas is its height / `RISE` exactly, so every feature climbs at one constant speed at every heat; wandering bases release fuel in puffs with a sharp start and a fast tail, so a puff necks and its let-go top climbs on while it burns away from below (smooth bursts get eaten from above and pulse in place); explicit clusters (one per 0.6 vh) with licks and dark gaps between over one warm bed; colour = temperature (amber cores low in thick tongues, orange bodies, deep red tips and let-go pieces); nothing below ~800 K, small and sparse up to ~1200 K, the tallest ~0.16-0.2 of the screen at 1811 K; heat only sets the bed's width, the tongues' height, brightness and colour, followed with a rate-limited ease; on the one clock as renderer `'thesis'`; no wave lines of their own, they bend a little with the swell via `swellGLSL`); a static CSS furnace on the flame palette (`--ember-hot` only at its core, from `--k` 0.3) holds the heat until the GL flames fade in (`data-gl`). ## Rules (from the PRD)
- Never write "LLC", "incorporated", a street address, or any payment details (Venmo etc.). Payment copy: "No payment until you've approved the design."
- No fabricated testimonials, client logos, reviews or stats. Showcase items stay labeled `Concept` until they are real clients.
- Colour means temperature. Ember (`--ember`) is the only accent and means hot (active, interactive, live): about 3 Ember elements per screen at most. `--ember-hot` only inside hot metal. Cooled surfaces flip to bone (`--cool`, `--ink`, `--ink-dim`, `--ember-deep` for Ember text on bone).
- Placeholders are marked `// TODO(jakob)`.
- Quality bar: Lighthouse mobile ≥ 95 on all four categories, `/sites` first-load JS well under 200 KB gzipped, no horizontal scroll at 360px, AA contrast, visible Ember focus rings.
- No gradient text and no second display face: hierarchy comes from Archivo's size, weight and width (`.wide`, `.h-display`, `.h-section`). The one exception is "alloyed" in the home opening, which is cast white-hot and cools (`.ig-cool`).
- Design rules live in `.claude/skills/unslop/SKILL.md`; `npm run unslop` checks what a machine can (headings without periods, no Instrument Serif or mono outside data, no wide-tracked caps, no decorative numbering, no dead zones on the home page).
